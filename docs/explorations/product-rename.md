# Product rename: Saci -> Jacurutu

Status: exploration — no implementation mandate
Disposition: promoted to brief 2026-08-17-product-rename — 2026-08-17
Origin: cost exploration run in the `buraqueira` repo, 2026-08-08; the *how* was
closed by the owner then, the *when* on 2026-08-16. Every figure below was
re-measured against `5ffbede` on 2026-08-17.
Roadmap link: would be a fourth entry under ROADMAP Identity shifts

The product is renamed to **Jacurutu**. The file is named for the topic and not
for the destination, because the destination has already moved once: the target
was *Nacurutu* until 2026-08-17, when no online reference to it could be found —
Jacurutu is the common Brazilian name for the great horned owl, Nacurutu only
the subspecies epithet. A name that changed twice in two days does not belong in
a path.

## Three decisions, closed

**It happens.** This note listed "whether the rename happens" as open. Closed by
the owner on 2026-08-16.

**It lands before `ship`, and the ordering is measured, not preferred.**
`.saci.json` is written today by `packages/cli/src/run-start.ts:44` into local
task folders only, because `ship` does not exist. No manifest has reached Drive
and no designer other than the owner holds one. Once `ship` runs, manifests live
in Drive across designers and renaming that filename stops being a local change
and becomes a migration across a distributed store.

**Scope is every live surface, never the historical record.** Measured over
tracked files at `5ffbede`:

```
$ git grep -io saci | wc -l                        1273   total
$ git grep -io saci -- docs/tasks docs/sessions automation | wc -l
                                                    938   record (74%)
                                                    335   live
```

In scope: 6 `package.json` names — five workspaces plus the root — the `bin`,
the three `.saci` runtime surfaces, the five `SACI_*` environment variables,
canonical docs, `.claude/`, `harness/`, `README.md`, and the repository name
local and remote.

Retained on purpose: `docs/tasks/**`, `docs/sessions/**`, `automation/`, and git
history. A recap that describes what shipped as `saci` becomes false if
rewritten, and `automation/` is a frozen provenance snapshot whose whole value
is being untouched. Retention here is a decision with a reason, not an oversight.

## The count is not stable, which is itself an argument

An earlier measurement on 2026-08-16 read 1259 total and 335 live at `0a7f05f`.
The 14-occurrence difference is `docs/explorations/dev-queue-board.md`, added by
#155 the following day — 12 of them live. The live surface grows with ordinary
work, so the cheapest moment to do this is always the earliest one.

A separate earlier figure of ~1,308 was inflated: it counted compiled `dist/`
output, which is gitignored and regenerated by the rename itself. Half the
matching files under `packages/` were `dist/`.

## The runtime surfaces, and why this is not one `refactor:`

The string `.saci` names three runtime surfaces, and `SACI_` names a fourth
class that this note did not previously mention:

- `CREDENTIALS_DIR_NAME` — the OAuth credentials directory. Declared **twice**:
  `packages/adapter-drive/src/constants.ts:15` exports it, and
  `packages/adapter-sheets/src/errors.ts:36` keeps a local copy even though
  `adapter-sheets` already depends on `adapter-drive`. Rename one and miss the
  other and it compiles, then fails at runtime.
- `IDENTITY_DIR_NAME` in `packages/cli/src/identity.ts` — the task-036 identity
  file, in the same `~/.saci`.
- `MANIFEST_FILENAME = ".saci.json"` in `packages/cli/src/run-start.ts:44` — the
  TaskManifest. (This note previously placed it in
  `packages/core/src/workspace.ts`, which holds only a comment about it.)
- **Five environment variables**, `SACI_TELEMETRY_DIR` in
  `.claude/hooks/lib/telemetry.mjs:28` and four `SACI_JIRA_*` / `SACI_IDENTITY_*`
  in `packages/cli/src/cli.ts`. These are the sharpest of the four, because they
  live in the owner's shell, outside the repository, where no read path reaches
  — and `grep -n 'SACI_' README.md` returns nothing, so the only copy of that
  contract is the code the rename rewrites.

`~/.saci` now has **three** consumers, not two: credentials, identity, and
`report.json` (`packages/cli/src/report-state.ts:22`), which arrived with #154.

**The owner chose a clean break** on 2026-08-17: no backward-compatible read
paths. A fallback keeps the string `saci` in the code permanently as the legacy
name being read, which relocates the word rather than removing it; and fallbacks
exist to protect installed users, of whom there is exactly one.

That choice inverts an argument this note used to make. A fallback would have
been the `refactor:`-compatible option, because it preserves behavior for
existing state. **The clean break is the one that cannot wear that label**: R14
requires identical output for the same input, and after the rename an unchanged
`~/.saci` plus unchanged exported variables yield a `saci fetch` that cannot
find its credentials. The mechanical surface is a genuine `refactor:`; the
runtime surfaces are a deliberate breaking change and take their own commit.

## Two traps that are not about naming

- `git worktree` stores **absolute** paths. Renaming the repository directory
  breaks every registered worktree at once — nine of them at the time of
  writing, and the number moves daily. The remedy is `git worktree repair`, and
  it belongs in the brief rather than being discovered live.
- One of the 21 `package-lock.json` matches is a false positive: `saCI` inside a
  base64 integrity hash. `package-lock.json` regenerates anyway, like `dist/`.

## Still not decided

Whether the "feature orchestrator" framing is adopted. That would be the fourth
identity shift; the previous three each cost dedicated doc-reconciliation work
(briefs 024, 025, 051), and it would change what `core` is allowed to contain —
a `core` question, not a naming one. It is deliberately not bundled here.
