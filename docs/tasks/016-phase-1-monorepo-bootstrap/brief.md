## Goal

Stand up the Saci v2 monorepo: four `@saci/*` packages compile via `tsc -b`
from a shared `tsconfig.base.json`, `node:test` runs a green placeholder
suite, and `node packages/cli/dist/cli.js --version` prints the CLI package
version. Promote two follow-up decisions to `docs/ROADMAP.md` §Pending
decisions.

Out of scope:

- Any domain logic (Phase 2 — `lib_transform.py` port).
- Any adapter implementation (Phase 4 — Jira REST, Google Sheets).
- Any CLI command beyond `--version` (Phase 3 production-flow commands,
  Phase 4 coordination commands).
- Bundling, packaging, signing, installer work (Phase 3+).
- Touching the v1 Electron codebase (`main.js`, `preload.js`,
  `psd-worker.js`, `renderer/`, `storage/`) — v1 is in freeze.
- Editing any section of `docs/MENTOR_BRIEF.md` other than §2 (only the
  one-line Node 22+ target addition in §2 is in scope — see Edit 7).
- Configuring CI / GitHub Actions (separate brief once Phase 1 lands).
- Installing or modifying the pre-commit hook (`.githooks/pre-commit` is
  not yet present in the repo today; introducing it is a separate `chore/`
  brief — see "Pre-commit hook state" note in Constraints below).
- Introducing any runtime dependency (devDependencies limited to
  `typescript` and `@types/node`).
- Choosing a final CLI library (deferred to Phase 2→3 transition — D4).
- Choosing a final versioning policy (deferred to Phase 4 — D5).
- Enabling `noUncheckedIndexedAccess` in `tsconfig.base.json` (deferred to

#### D1 — Package boundaries

- Layout: `packages/<name>/` for each of the four workspaces.
- Names: `@saci/core`, `@saci/adapter-jira`, `@saci/adapter-sheets`,
  `@saci/cli`.
- Every package declares `"private": true` in `package.json`.
- Only `@saci/cli` declares the `bin` field:
  `"bin": { "saci": "./dist/cli.js" }`.
- Internal dependencies are declared explicitly in each `package.json`.
  Example for `@saci/cli`:
  `"dependencies": { "@saci/core": "*", "@saci/adapter-jira": "*",
  "@saci/adapter-sheets": "*" }`.
- `@saci/adapter-jira` and `@saci/adapter-sheets` declare
  `"dependencies": { "@saci/core": "*" }`.
- `@saci/core` declares no internal dependencies.

#### D2 — TypeScript configuration

- `tsconfig.base.json` at the repo root; each package's `tsconfig.json`
  extends it via `"extends": "../../tsconfig.base.json"`.
- Base `compilerOptions`:
  - `"target": "ES2022"`
  - `"module": "NodeNext"`
  - `"moduleResolution": "NodeNext"`
  - `"strict": true`
  - `"esModuleInterop": true`
  - `"skipLibCheck": true`
  - `"forceConsistentCasingInFileNames": true`
  - `"declaration": true`
  - `"declarationMap": true`
  - `"sourceMap": true`
  - `"outDir": "./dist"`
  - `"rootDir": "./src"`
- Project references: every package's `tsconfig.json` declares
  `"composite": true` (inherited from base). The root `tsconfig.json`
  declares `"references"` pointing at the four packages and is the entry
  point for `tsc -b`.
- `noUncheckedIndexedAccess` is **deferred to Phase 2**. Do not include it
  in `tsconfig.base.json` now.

#### D3 — Test runner integration (Option A — compile-and-test)

- `tsc` compiles `*.test.ts` files alongside source into
  `dist/**/*.test.js`.
- `node --test` runs the compiled `.js` files from `packages/*/dist/`.
- Root `package.json` declares scripts:
  - `"build": "tsc -b"`
  - `"test": "node --test packages/*/dist/**/*.test.js"`
- Zero new runtime dependencies (R2 compliant).
- Migration to `--experimental-strip-types` (Option C) remains a reversible
  future change once Node ≥ 23.6 stabilizes the flag. **Do not include any
  scaffolding for it now.**

#### D4 — CLI library (Phase 1 only — `node:util` `parseArgs` builtin)

- The CLI uses Node's builtin `parseArgs` from `node:util` (Node 18.3+).
- Subcommand dispatch is a manual `switch` over `argv` after parsing.
- Phase 1 requires only the `--version` flag. The CLI reads its own
  `package.json` via an ESM import attribute
  (`import pkg from "../package.json" with { type: "json" }`) and prints
  `version` to stdout. Requires `target: ES2022` and
  `module/moduleResolution: NodeNext` in `tsconfig.base.json` (D2) plus
  `resolveJsonModule: true` in `packages/cli/tsconfig.json`. The
  printed `version` reflects the **internal `@saci/cli` package
  version** (`0.0.0` per D5); product versions live in git tags on root
  until Phase 4 (D5). This is intentional — the CLI's `--version`
  becomes product-meaningful when D5 closes.
- The final library choice (commander / citty / continue with builtin) is
  **deferred to the Phase 2→3 transition**. Edit 6 promotes this deferral
  to `docs/ROADMAP.md` §Pending decisions.

#### D5 — Versioning policy (defer)

- Every `package.json` carries `"version": "0.0.0"`.
- No release tooling (no changesets, no version-bump scripts) is
  introduced now.
- Milestones are marked via git tags on root (`v0.1.0`, `v0.2.0`, etc.) —
  outside the scope of this brief.
- The final policy (single vs. independent vs. continued defer) is
  **deferred to Phase 4**. Edit 6 promotes this deferral to
  `docs/ROADMAP.md` §Pending decisions.
